$ xray-up

Builds the one command that turns a clean Debian 12/13 VPS into a hardened Xray server (VLESS + XHTTP + REALITY). Nothing you type here leaves this page; the root password is asked for by ssh in your terminal.

3. Save the output

  

    
The run ends with one summary block. It holds the vless:// link, the new SSH port, the admin user and its password. The password is printed once and stored nowhere, so copy the block into your password manager before closing the terminal.

    
Lost it? Log in as root on the provider's web console and run passwd vpsadmin.

  


  
What the script does

  

    
    
      
  1. Checks from the server that the SNI site speaks TLS 1.3 and negotiates ALPN.
    2. 
      
  2. Installs a pinned, checksum-verified Xray release as a systemd service with one VLESS + XHTTP + REALITY inbound on a random path.
    3. 
      
  3. Turns on automatic security updates, with a reboot at 04:30 server time when a new kernel needs it.
    4. 
      
  4. Creates a sudo user with a 32-character random password.
    5. 
      
  5. Moves SSH to a new port, disables root login, allows only the admin user.
    6. 
      
  6. Loads an nftables firewall: inbound SSH, the Xray port and ICMP only.
    7. 
    

  


  
Client apps

  

    
XHTTP needs a client built on a recent Xray core, for example a current v2rayN, v2rayNG, Hiddify, Happ, Streisand or v2RayTun. Import the vless:// link; if the app shows the transport as "tcp", it is too old.

  


  
Choosing the SNI

  

    
    
      
  • A real third-party HTTPS site that you do not control and that is reachable without the proxy.
    • 
      
  • It must support TLS 1.3. HTTP/2 is preferred; a site with no ALPN at all does not work.
    • 
      
  • Use the exact hostname that serves the site, not one that only redirects elsewhere.
    • 
      
  • A site hosted near the server's own network is a more believable choice than a random famous one.
    • 
    

  


  
Afterwards

  

    
Log in with the new port and user, then use the copy of the script that was installed on the server:

    
    
      
  • ssh -t -p PORT USER@SERVER sudo xray-up --show prints the link again.
    • 
      
  • sudo xray-up --rotate issues a new UUID, keys, short ID and path. The old link stops working.
    • 
      
  • sudo xray-up --upgrade --xray-version latest replaces the Xray binary and refreshes the geodata.
    • 
    

    
Running the deploy command a second time changes nothing. Root can no longer log in over SSH, so it fails at the password prompt.
